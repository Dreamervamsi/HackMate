# Code Validation Phase Implementation Plan

## Overview

This document outlines the implementation of the code validation phase for the HackMate project. The validation phase automatically tests, validates, and fixes bugs in code generated by implementation agents using Docker containers for isolation.

## Architecture

### Components Implemented

1. **Bug Resolver Agent** (`agents.py`)
   - Function: `resolve_bug(code, test_results)`
   - Purpose: Fixes syntax, logical, and deprecation errors
   - Input: Code with bugs + test results
   - Output: Clean, bug-free code

2. **Test Generation Agent** (`agents.py`)
   - Function: `generate_tests(code, language)`
   - Purpose: Generates comprehensive tests
   - Input: Code to test + programming language
   - Output: Complete test suite

3. **Python Validation Agent** (`agents.py`)
   - Function: `validate_python_code(code, test_code)`
   - Purpose: Validates Python code in Docker containers
   - Environment: `python:3.11-slim` Docker image
   - Security: Network isolation, resource limits, non-root user

4. **Validation Workflow** (`agents.py`)
   - Function: `validate_code_with_autofix(code, language, max_attempts)`
   - Purpose: Orchestrates validation with auto-fix loop
   - Auto-fix: Maximum 2 attempts (configurable)

### Integration Points

- **Orchestrator** (`orchestrator.py`): Added `validate_code_with_autofix` to tool list and workflow
- **Models** (`models.py`): Added validation-related Pydantic models
- **API Documentation** (`API_DOCUMENTATION.md`): Complete validation phase documentation

## Validation Workflow

### Process Flow

```
Implementation → Test Generation → Docker Validation → Bug Detection → Bug Resolver → Re-validation (max 2x) → Final Result
```

### Detailed Steps

1. **Test Generation**
   - Agent analyzes implemented code
   - Generates comprehensive unit tests
   - Covers edge cases and error conditions

2. **Docker Validation**
   - Code + tests run in isolated container
   - Network isolation for security
   - Resource limits (CPU, memory, timeout)
   - Test results captured

3. **Bug Detection**
   - Analyze test results for errors
   - Identify syntax, logical, runtime errors
   - Detect deprecation warnings

4. **Bug Resolution** (if needed)
   - Bug Resolver Agent analyzes code + errors
   - Fixes identified issues
   - Maintains original functionality

5. **Re-validation**
   - Fixed code re-tested in Docker
   - Process repeats if errors persist
   - Maximum 2 auto-fix attempts

6. **Final Result**
   - Validated code returned if successful
   - Error report if validation fails

## Security Features

### Docker Isolation
- **Network**: `--network none` (no external access)
- **Resources**: 512MB memory, 1 CPU core limit
- **Filesystem**: Read-only with tmpfs for /tmp
- **User**: Non-root user (uid 1000)
- **Privileges**: `no-new-privileges` security option

### Code Execution Safety
- **Timeout**: 30-second limit per validation
- **Ephemeral**: Containers auto-removed (`--rm`)
- **Sandbox**: Complete isolation from host system

## Usage Examples

### Manual Validation

```python
from agents import validate_code_with_autofix

code = """
def add(a, b):
    return a + b
"""

result = validate_code_with_autofix(code, "python", max_attempts=2)
if result["success"]:
    print("Validated code:", result["validated_code"])
else:
    print("Validation failed:", result["error"])
```

### Bug Resolution

```python
from agents import resolve_bug

buggy_code = """
def divide(a, b):
    return a / b  # No error handling
"""

test_results = "ZeroDivisionError: division by zero"

result = resolve_bug(buggy_code, test_results)
if result["success"]:
    print("Fixed code:", result["fixed_code"])
```

### Test Generation

```python
from agents import generate_tests

code = """
def calculate_area(length, width):
    return length * width
"""

result = generate_tests(code, "python")
if result["success"]:
    print("Generated tests:", result["test_code"])
```

## Integration with Orchestration

The validation phase is automatically triggered after implementation:

1. Orchestrator calls `implement_plan`
2. Implementation agent generates code
3. Orchestrator automatically calls `validate_code_with_autofix`
4. Validation runs in Docker with test generation
5. Bugs are auto-fixed if detected (max 2 attempts)
6. Final validated code returned to user

## Error Handling

### Docker Not Available
```
Error: "Docker is not installed or not running. Code validation requires Docker."
Solution: Install and start Docker
```

### Validation Timeout
```
Error: "Validation failed: Code execution timed out (possible infinite loop)."
Solution: Check code for infinite loops or long operations
```

### Max Attempts Reached
```
Error: "Validation failed after 2 attempts"
Solution: Review error details, manually fix code, or increase max_attempts
```
